# Data schema v3

Schema 3 is the current data format. It can hold several sources, each with its own generated file. One source ships:
the generated leveling lists.

| Source id | File | Shipped |
|-----------|------|---------|
| `leveling` | `ForeverBiS/ForeverBiS_Data_Leveling.lua` | yes |
| `kamilabs` | `ForeverBiS/ForeverBiS_Data_KamiLabs.lua` | no: generated only with `--include-unshipped`, pending permission from the site owner |

`UpdateForeverBiS.py` writes these files from the modules in `bis_sources/`. `ForeverBiS_Model.lua` (loaded after the data files, see the `.toc`) reads them and builds the legacy globals the UI uses (`ForeverBiSLists`, `ForeverBiSItemIDs`, `ForeverBiSBuildLabels`) for the active source. `ForeverBiSLists` holds one lazy entry per route that is filled on first read. The model never reads `ForeverBiSDB`. The old single file `ForeverBiS_Data.lua` no longer exists; [schema 2](data-schema-v2.md) described it. The ForeverChanges (`foreverchanges`) and wowsims gear-preset (`wowsims`) sources were removed; see [Settings API](#settings-api) for players who had chosen them.

## Quick path

1. A data file adds one source to the wrapper `ForeverBiSData`.
2. The model reads the default source (`leveling`). There is no source picker or source dropdown.
3. To add a source, follow [Extending](#extending).

## Wrapper and source entry

Every data file runs the same wrapper line, then registers its own source under its id:

```lua
ForeverBiSData = ForeverBiSData or { schema = 3, sources = {} }
ForeverBiSData.sources["leveling"] = {
  label = "ForeverBiS",
  order = 0,
  url = "https://github.com/wowsims/forever",
  phases = {
    { id = "lvl30", label = "Level 30", level = 30 },
  },
  lists = {
    ["druid/feral"] = {
      label = "Feral",
      phases = {
        lvl30 = { title = "...", slots = { ... } },
      },
    },
  },
}
```

| Field | Meaning |
|-------|---------|
| `label` | Name of the source, shown in the empty state when it has no list for a route |
| `order` | Display order, ascending; ties are broken by id |
| `url` | Where the lists or their data come from |
| `phases` | Ordered, oldest first. Each phase is `{ id, label, level? }`; `level` is optional |
| `lists` | Route to list, same shape as schema 2 (see [Lists](#lists)) |

Because each file only adds its own key to `sources`, the files can load in any order. A file with another schema is ignored by the model.

Phases belong to their source. The bracket dropdown of the BiS window only shows the phases of the active source, and two sources may use the same phase id for different data.

Routes also belong to their source. The first segment of a route is the class key (`druid`, `warrior`, ...), and a source only has routes for the classes and specs it covers.

## Per-source specifics

| Source | Order | Phases | Coverage | Item sources |
|--------|-------|--------|----------|--------------|
| ForeverBiS (`leveling`) | 0 | `lvl20` to `lvl50` "Level N", `lvl60` "Level 60 (pre-raid)" | Generated: 26 PvE routes, every class | Structured, from `db.json` (see below) |
| Kami Labs | 2 | `lvl30` "Level 30", `lvl60` "Level 60 (pre-raid)" | One item per slot | Structured |

- **ForeverBiS (`leveling`).** Generated by `bis_sources/leveling.py`, not copied from a guide. For each route and level bracket it takes every item of the wowsims database (`assets/database/db.json`, MIT) that the class can equip at that level and whose required level is at most the bracket, scores it as Σ stat × weight (plus weapon DPS × the `MainHandDps`/`OffHandDps`/`RangedDps` weight), and keeps the 6 best per slot. Weights come from the wowsims EP presets (`presets.ts`, or `druid/feral_ep.ts` for feral); Restoration Druid, Holy and Protection Paladin, Restoration Shaman, Mage and Warlock have none upstream, so `ROUTES` in `leveling.py` carries weights written for ForeverBiS. Items that are phase 2, random-suffix, below green quality or only a PvP reward are left out, and `lvl60` leaves raid drops out. Every raid drop in the database is phase 2 and tier sets are missing, so there is no raid phase. Casters' two-handers must beat a one-hander plus the best off hand. Lists carry no enchants. Faction-only items get `faction`.
- **Item sources.** `bis_sources/sources_text.py` describes where each item comes from, from the item's `sources` in `db.json`: a dungeon drop first, then any drop, crafted, quest, vendor, reputation and PvP, written as text ("Boss, Zone", "Quest: Name (Alliance)", "Sold by NPC, Zone", the profession name, "Reputation: X", "PvP reward"). `structure_source()` turns that text into the structured source. Items with no `sources` keep `{ kind = "unknown", text = "Source not listed by wowsims" }`:

  ```lua
  { id = 10250, name = "Master's Hat", source = { kind = "unknown", text = "Source not listed by wowsims" } },
  ```
- **Drop chances.** `bis_sources/eglink.py` reads the `loot` and `encounters` datasets of every live client build (product `wowf`, never the `wow_classic_beta` beta) from [JIVESCORP/eg-link-output-wowf](https://github.com/JIVESCORP/eg-link-output-wowf) (CC BY 4.0; Data from Efficient Games (https://efficient.games), licensed under CC BY 4.0.) and sets `dropRate` on a drop source:
  - Kills only: corpse keys `npc:<id>`, with or without `|quest` and `|group`. Skinning and pick pocket (`|spell:<id>`), objects, containers and fishing are left out.
  - Keys are pooled across builds as Σ `chance` × `windows` / Σ `windows`; a key of the NPC that does not list the item counts as kills without a drop.
  - A dungeon boss (an NPC in an encounter's `bosses`) leaves its `|group` corpse keys out, because another member often loots the rolled item first, and adds its `rolls` instead (`drops` / (`kills` + `unconfirmed`)), only for roll keys whose loot threshold the item's quality reaches.
  - A rate needs at least 10 pooled observations (loot windows plus rolled kills), the minimum EG Link itself uses before trusting a corpse share; an item that never dropped gets none. The percent has one decimal (two under 0.1%) and is capped at 100.
  - The rate is the one of the NPC the wowsims drop names, never another NPC's. A dungeon drop that names no NPC (trash, "Multiple NPCs") takes the NPC with the most observations among those that dropped it; a world drop that names no NPC gets none.
  - If EG Link cannot be read, or its license is no longer CC BY 4.0, the lists are written without drop rates and the run logs a `::warning::`.
- **Kami Labs.** Level 30 and Level 60 (pre-raid) lists, one item per slot, with structured sources. Its file is only generated with `--include-unshipped` and is not shipped.

## Lists

The `lists` shape is unchanged from schema 2:

```lua
["druid/balance"] = {                                           -- route, same keys as the site
  label = "Balance",
  phases = { lvl30 = { title = "...", slots = {
    { slot = "Head",
      items = { { id = 252504, name = "...", source = { kind = "profession", text = "...", skill = "Leatherworking" } } },
      enchants = { { effect = "Agility +5", spell = "...", source = "...", formulaId = 249504 } } },
  } } },
},
```

### Item shape

- `items` order is the rank. `id` is omitted when unknown. `enchants` is omitted when empty.
- `source.text` is the raw string from the source (lossless). `source.kind` is one of `quest`, `profession`, `dungeon`, `world`, `unknown`. `unknown` is used for items whose `db.json` entry has no source.
- Optional `source` fields, set only when detected: `faction` ("Horde"/"Alliance", exclusive sources only), `zone`, `boss`, `dropRate` (number, percent), `quest`, `skill`, `skillLevel`, `bindsToMaker`, `reported`, `craftedBy` (the profession that can also make an item whose `kind` is not `profession`, for example a world drop; the tooltip shows it as "Crafted by").

## Model API

Source functions:

- `ForeverBiSModel.DEFAULT_SOURCE` is `"leveling"`. The model starts on it, or on the first source when it is missing.
- `ForeverBiSModel.sources()` returns the registered sources as `{ id, label, url }`, ordered by `order`, then id.
- `ForeverBiSModel.activeSource()` returns the id the model reads.
- `ForeverBiSModel.select(id)` makes a source active, rebuilds the legacy globals and resets the `bisIndex`. It returns `false` and changes nothing for an unknown id.

Every other function operates on the active source:

- `phases(route)`, `defaultPhase(route)` (latest available), `label(route)`, `list(route[, phaseId])` (legacy `{title, slots}` shape), `gridSlots(route[, phaseId[, limit]])` (the BiS window's rows: `{ slot, key, items = { { id, name, source } } }`, at most 6 items per slot by default), `bracketForLevel(route, level)`, `availablePhase(route, phaseId)`, `slotKey(name)`, `routes()` and `buildLegacy()`.
- `Lists.view` returns `missing = true` when the active source has no list for the route.
- `Catalog.refreshBuilds(labels)` restores the built-in builds first, so it can be called again after the data changes.

`ForeverBiSModel.bisEntries(itemId, itemName)` answers "where is this item BiS?" from a reverse index built lazily on first use (and reset by `buildLegacy` and `select`). It returns `{ route, class, phase, phaseLabel, slot, rank, label }` entries in route, phase and slot order, where `class` is the first route segment and `rank` the 1-based position in the slot. The id is matched first; the exact name only matches data rows that have no `id`. An item repeated in one slot list yields one entry, and unknown items, nil arguments or missing data yield an empty list. The tooltip (`ForeverBiS_Tooltip.lua`), the BiS stars (`UI/BisStar.lua`) and the loot alerts consume it, and it reads the active source.

`bracketForLevel` returns the bracket the window and the tooltip use by default (the BiS stars apply the same rule): among the phases the route has data for, the numeric-`level` phase with the highest level that is <= the player's level (a level-25 character gets `lvl20`). Below every numeric phase, or with a nil/invalid level, it returns the lowest one; a route without numeric phases returns its default phase, and an unknown route nil. `availablePhase` returns a saved phase id only if the route has it (else nil, meaning automatic). `Settings.bracket(route, level)` combines both: the bracket the player picked when the route has it, otherwise `bracketForLevel`; the loot alerts, `/bis link` and the dungeon notice read it.

## Settings API

`ForeverBiSDB.source` (account-wide) is the source id an older version saved when the player picked a source. Nothing
writes it any more, and `Core/Settings.lua` is the only file that reads it.

- `Settings.bind()` activates the saved source when it ships. Otherwise, as for `foreverchanges` and `wowsims`, which
  no longer ship, it falls back to the default source (`leveling`) without an error and without clearing the saved id.
- `Settings.activeSource()` returns the id the model reads.
- The window opens straight on the lists: there is no source picker or source dropdown. Saved builds that the leveling
  lists do not have resolve to the class's first build, and a saved phase the route lacks reads as automatic.
- The `bySource` table older versions saved per character (the build and phase remembered per source) is no longer
  read or written.

## Slot keys

`ForeverBiSModel.slotKey(name)` normalizes a list slot name to a canonical key: `Head`, `Neck`, `Shoulder`, `Back`, `Chest`, `Wrist`, `Hands`, `Waist`, `Legs`, `Feet`, `Finger`, `Trinket`, `Main Hand`, `Off Hand`, `Ranged`. `Two-hand weapon` normalizes to `Main Hand`, both off-hand variants to `Off Hand`, and `Relic` (idol, libram or totem) to `Ranged`, like a `Ranged` slot. The BiS window uses these keys to match equipped and inspected items to their row. Unknown names come back unchanged.

## Updater

`UpdateForeverBiS.py` is a CLI over the `bis_sources/` package:

- `bis_sources/__init__.py` is the registry. Each `Source` has an `id`, a `file_name`, a `label`, an `order`, a `url`, a `ship` flag and a `fetch()` function.
- `bis_sources/common.py` holds the shared HTTP helpers, the validation and the schema 3 Lua emitter.
- `bis_sources/leveling.py` and `bis_sources/kamilabs.py` are the source modules. Each `fetch()` returns `(data, labels, phases)`.
- `bis_sources/sources_text.py` describes item sources from the wowsims item database (`SourceDescriber`) and structures the text (`structure_source()`).
- `bis_sources/eglink.py` pools the EG Link loot data into drop chances (`load()`, `DropRates`).

Flags:

- `python3 UpdateForeverBiS.py ForeverBiS` updates every shipped source.
- `--include-unshipped` also updates sources with `ship = False`.
- `--only <id>` (repeatable) updates just the named sources, shipped or not.

Failure guard: each source is fetched, validated and written atomically. A failing source keeps its previous file and prints a `::warning::`. The other sources are still written. The run exits with a non-zero status when any shipped source failed (after writing the ones that succeeded), or when every attempted source fails; a failing unshipped source (for example Kami Labs with `--include-unshipped`) does not change the exit status.

Shrink guard: if a source no longer returns a route its committed `ForeverBiS_Data_<Source>.lua` has, that source fails and keeps its old file, naming the missing routes. Pass `--allow-shrink` when removing routes is intended.

The workflow `.github/workflows/update-lists.yml` stages `ForeverBiS/ForeverBiS_Data_*.lua`, and when any of them changed it commits them to `develop`, tags the next stable version (`vX.Y.Z`, patch bumped) and releases it.

## Extending

- **New phase.** Each source declares its phases in its module (`PHASES` in `leveling.py`, `TIERS` in `kamilabs.py`). The phase list of a source is its sorted union of phases, by level.
- **New source kind.** Add the check in `structure_source()` in `bis_sources/sources_text.py`, add the kind to `SOURCE_KINDS` in `bis_sources/common.py`, and add the kind to `VALID_KINDS` in `tests/data_spec.lua`.
- **New dungeon or raid.** Add a `(lowercase match, display name)` row to `DUNGEON_SOURCES` in `bis_sources/sources_text.py`, which also makes it a `dungeon` kind, and the same row to `Sources.dungeons` in `ForeverBiS/Core/Sources.lua` (the addon's dungeon notice); keep both lists identical. Add it to `EXTRA_ZONES` to fill only `zone` and `boss`.
- **New source.**
  1. Add `bis_sources/<name>.py` with a `fetch()` that returns `(data, labels, phases)`, with `data` mapping route to phase to `(title, slots)`, as `common.validate` and `common.emit_lua` expect.
  2. Add a `Source(...)` entry to `SOURCES` in `bis_sources/__init__.py`. Set `ship = False` until it may ship.
  3. Add a line `ForeverBiS_Data_<file_name>.lua` to `ForeverBiS/ForeverBiS.toc`, before `ForeverBiS_Model.lua`.
  4. Add tests under `tests/python` (the fixtures are in `tests/python/fixtures`).

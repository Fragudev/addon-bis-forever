# Data schema v2

`ForeverBiS/ForeverBiS_Data.lua` is generated by `UpdateForeverBiS.py` and defines only the global `ForeverBiSData`.
`ForeverBiS_Model.lua` (loaded right after it, see the `.toc`) reads it and builds the legacy globals the UI uses
(`ForeverBiSLists`, `ForeverBiSItemIDs`, `ForeverBiSBuildLabels`). The model never reads `ForeverBiSDB`.

## Shape

```lua
ForeverBiSData = {
  schema = 2,
  phases = { { id = "lvl30", label = "Level 30", level = 30 } },   -- ordered, oldest first
  lists = {
    ["druid/balance"] = {                                           -- route, same keys as the site
      label = "Balance PvE",
      phases = { lvl30 = { title = "...", slots = {
        { slot = "Head",
          items = { { id = 252504, name = "...", source = { kind = "profession", text = "...", skill = "Leatherworking" } } },
          enchants = { { effect = "Agility +5", spell = "...", source = "...", formulaId = 249504 } } },
      } } },
    },
  },
}
```

- `items` order is the rank. `id` is omitted when unknown. `enchants` is omitted when empty.
- `source.text` is always the raw ForeverChanges string (lossless). `source.kind` is one of `quest`, `profession`,
  `dungeon`, `world`, `unknown`. The classification mirrors `getSourceCategory` in `ForeverBiS.lua`;
  `unknown` is used for "Where it comes from is not known yet".
- Optional `source` fields, set only when detected: `faction` ("Horde"/"Alliance", exclusive sources only), `zone`,
  `boss`, `dropRate` (number, percent), `quest`, `skill`, `skillLevel`, `bindsToMaker`, `reported`.

## Model API

`ForeverBiSModel.phases(route)`, `.defaultPhase(route)` (latest available), `.label(route)`,
`.list(route[, phaseId])` (legacy `{title, slots}` shape), and `.buildLegacy()`.

## Extending

- **New phase**: `phase_from_title()` derives it from the list title ("... at level 60" gives `lvl60`); no code change
  is needed once the page title carries the level. Real discovery from ForeverChanges is pending because its
  post-launch page structure is unknown. The phase list is the sorted union of all lists, by level.
- **New source kind**: add the check in `structure_source()` (and keep `getSourceCategory` in sync if the UI should
  filter on it), then add the kind to `VALID_KINDS` in `tests/data_spec.lua`.
- **New dungeon or raid**: add a `(lowercase match, display name)` row to `DUNGEON_SOURCES` in the updater (this
  also makes it a `dungeon` kind, so mirror it in `dungeonSourceNames`), or to `EXTRA_ZONES` to only fill `zone`/`boss`.
